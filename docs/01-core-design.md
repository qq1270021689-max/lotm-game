# 《诡秘之主》文字模拟游戏 · 核心设计文档 v0.1

> 类型定位：文字 + 数值模拟 | 技术栈：TypeScript Web 游戏 | 首发规模：5 条途径
>
> ⚠️ IP 说明：本文档暂用原著名词（途径名、序列名、配方名）作为占位。若最终走原创换皮路线，阶段 4 内容量产前需全局替换名词表；玩法规则本身不受影响。

## 1. 游戏概述

- **一句话体验**：在 24 小时制蒸汽都市中，平衡凡人生活与非凡者之路——每一次时间分配都在积累力量、金钱、人脉，或疯狂。
- **玩法参照**：密教模拟器（行动槽 + 倒计时 + 压迫循环 + 碎片叙事）× 太吾绘卷（沙盒人生 + NPC 自主生活 + 长线经营），纯文字版。玩法层详见 `02-gameplay-loop.md`。
- **视角**：单主角，第一人称文字叙述 + 数值面板。
- **核心循环（单日）**：
  ```
  起床结算 → 分配 24 小时（生活/工作/社交/扮演/冒险）
    → 行动结算 + 事件触发 → 夜晚结算（消化度/污染/经济）
    → 睡眠 → 次日世界状态推进（NPC 日程、委托刷新、剧情推进）
  ```
- **终极压力**：序列越高越强，但污染与失控风险越大；时间永远不够用。

## 2. 时间系统规则（核心系统①）

### 2.1 基本单位

- 1 游戏日 = **24 小时 = 24 个 tick**，所有行动以小时为单位消耗。
- 主角默认每天 00:00 在自己住所（或昏迷地点）进入新的一天。

### 2.2 时段划分（影响事件池与 NPC 在岗状态）

| 时段 | 小时 | 特征 |
|---|---|---|
| 深夜 | 0–5 | 黑市、非凡事件高发；正常人 NPC 不可交互 |
| 清晨 | 6–8 | 教堂晨祷、市场开摊 |
| 上午 | 9–11 | 工作时段、官方机构开放 |
| 中午 | 12–13 | 午餐社交窗口 |
| 下午 | 14–17 | 工作时段、委托交付 |
| 黄昏 | 18–19 | 下班、酒馆预热 |
| 夜晚 | 20–23 | 酒馆社交高峰、隐秘集会 |

### 2.3 行动时长表（示例，数值待平衡）

| 类别 | 行动 | 耗时 | 主要产出 |
|---|---|---|---|
| 生活 | 正餐 | 1h | 精力 +15，小概率社交事件 |
| 生活 | 睡眠 | 6–8h | 精力全恢复，理智 +10 |
| 生活 | 购买/搬家 | 1–2h | 经济结算 |
| 工作 | 本职上班 | 8h | 薪水 + 职业技能 + 人脉 |
| 工作 | 兼职/零工 | 2–4h | 少量金钱 |
| 社交 | 拜访 NPC | 1–2h | 好感/情报/委托 |
| 扮演 | 途径扮演行为 | 1–4h | 消化度（见 §4.2） |
| 学习 | 神秘学阅读/仪式练习 | 2–3h | 灵性强韧、仪式完成度 |
| 冒险 | 非凡委托/探索 | 4–8h | 材料、金钱、封印物、污染风险 |
| 特殊 | 服食魔药晋升 | 1h + 判定 | 见 §4.3 |

### 2.4 精力与睡眠

- **精力值 ENERGY（0–100）**：普通行动 −5～−10/h，战斗/冒险 −20/h。
- 精力 < 20：所有判定 −30%，触发「疲惫」事件池。
- 精力 = 0：强制昏迷 8h，触发袭击/抢劫风险判定。
- **睡眠豁免**：不眠者途径（§5.4）免除睡眠需求——每天凭空多出 6–8h，但污染自然增速 +50%（途径代价）。

### 2.5 NPC 作息表

每个 NPC 拥有一张 24h 作息表（见 §7 模板）。玩家只能在 NPC 处于对应地点/状态时与其交互。**NPC 不等待玩家**——委托有期限、集会按时发生、线人过时不候。

## 4. 晋升体系总规则（核心系统②）

### 4.1 晋升三要素

1. **魔药**：主材料（核心非凡特性来源）+ 辅助材料。集齐后可自行调配（仪式技能判定）或付费请人调配。
2. **消化度 100%**：通过扮演法消化当前序列魔药（见 4.2）。未消化满强行晋升 = 高失控率。
3. **晋升仪式**：序列 5 及以上需要（低序列仪式简化）。仪式有完成度数值。

### 4.2 扮演法游戏化

- 每个序列定义 **3–5 条「扮演守则」**（如占卜家：「常做占卜，但敬畏命运」）。
- 执行符合守则的行动 → `+消化度`（单次 +1%～+5%，关键剧情扮演 +10%）。
- 违背守则（如占卜家滥杀、观众暴露非凡身份）→ `−消化度` 且 `+污染`。
- 消化度 ≥ 80% 后增速减半（「最后一口魔药最难消化」）。
- **真谛事件**：消化度到 50%/80% 时各触发一次途径专属剧情，完成后解锁额外扮演加成。

### 4.3 晋升判定公式（初版）

```
成功率% = 20 + 消化度×0.45 + 仪式完成度×0.25 + 辅助材料品质(0~10) + (SAN−50)×0.2 − COR×0.3
```

- 成功：晋升，全属性 +序列加成，解锁新能力，消化度清零。
- 失败：进入失控判定 `失控率 = COR×0.5 + (100−成功率)×0.3`：
  - 未失控：重伤 + 污染 +15 + 材料作废。
  - 失控：根据途径生成异变剧情（可救回→堕入野生非凡者线；不可救→游戏结束）。

### 4.4 序列数值加成倾向

每条途径有明确的属性成长倾向（见 §5 各表「成长倾向」列），保证 5 条途径玩法分化。

## 6. 非凡特性守恒与封印物（核心系统④）

### 6.1 守恒定律数据化

- 每条途径、每个序列的非凡特性**总量恒定**（数据库中登记为全局常量，如占卜家途径序列 9 特性现存 417 份——数字仅示例）。
- **死亡析出**：非凡者死亡后，体内特性在 1 小时内析出为可拾取物品「非凡特性（途径/序列）」。拾取、销毁、被教会收容都会更新全局账目。
- **聚合与分离**：高序列特性可在仪式下分离出低序列特性（分离 1 份序列 7 ≈ 得 1 份序列 8 + 若干序列 9，具体兑换表按途径登记）；低序列难以自然聚合，须通过服食晋升在人体内完成。
- **游戏意义**：玩家杀死的每个非凡者都会真实改变世界的超凡分布——教会序列者的缺员、黑市材料价格波动（材料稀缺度 = 1/现存份数）、隐秘组织的招募动作，全部从这本「特性总账」驱动。

### 6.2 封印物分级

| 等级 | 危险度 | 收容要求 | 示例定位 |
|---|---|---|---|
| 3 级 | 低 | 普通封印盒，登记即可 | 小副作用的实用道具 |
| 2 级 | 中 | 专用收容间，限权使用 | 强力但有明确代价 |
| 1 级 | 高 | 多重封印，小队级审批 | 可改变一场战役 |
| 0 级 | 灾厄 | 教会最高密级，剧情锁定 | 主线级，不可常规获取 |

**封印物数据字段**：编号 / 名称 / 外观描述 / 来源（哪位死者特性或天然形成）/ 正面能力 / 负面效果（必触发）/ 收容方式 / 使用代价 / 当前持有者。

**示例（占位原创）**：

> **2-107「无眠者的怀表」**：指针永远指向持有者的死期。正面：持有期间免疫睡眠与梦境入侵；负面：每天 SAN −3，且周围 10 米内的钟全部停摆，极易暴露。收容：浸泡于圣水的铅盒。

## 8. TypeScript 数据结构（对接阶段 3 原型）

```ts
// ---- 时间 ----
interface GameTime { day: number; hour: number; } // hour: 0-23

// ---- 主角 ----
interface PlayerStats {
  phy: number; spi: number; mnd: number; cha: number;
  san: number; cor: number; energy: number;
  money: { pounds: number; soli: number; pence: number };
  pathwayId: string | null;
  sequenceLevel: number | null;   // 9..0
  digestion: number;              // 0-100，当前序列消化度
  tags: string[];                 // 状态标签
}

// ---- 途径与序列 ----
interface Pathway { id: string; name: string; tendency: string; sequences: SequenceDef[]; }

interface SequenceDef {
  level: number;                  // 9..0
  name: string;
  abilities: AbilityDef[];
  actingPrinciples: string[];     // 扮演守则
  potion: PotionFormula | null;   // 服食本序列所需魔药（序列9为入门药）
  ritual: RitualDef | null;
}

interface PotionFormula {
  main: Ingredient[];
  aux: Ingredient[];
}
interface Ingredient { itemId: string; qty: number; }
interface RitualDef { description: string; completion: number; } // completion 0-100
interface AbilityDef { id: string; name: string; description: string; costPerUse?: number; }

// ---- NPC ----
interface NPCDef {
  id: string; name: string;
  publicIdentity: string; secretIdentity?: string;
  pathwayId?: string; sequenceLevel?: number;
  schedule: { from: number; to: number; locationId: string; interactable: boolean }[];
  motives: string[]; secrets: string[]; personalityTags: string[];
  relationHooks: { threshold: number; effect: string }[];
  onDeath?: string;
}

// ---- 事件 ----
interface EventDef {
  id: string;
  trigger: {
    hours?: number[]; locationIds?: string[];
    minStats?: Partial<PlayerStats>; tagsAny?: string[];
    pathwayId?: string; sequenceMax?: number;
  };
  weight: number;                 // 随机权重
  once?: boolean;
  choices: { text: string; requirements?: string; effects: Effect[] }[];
}
interface Effect { op: 'addStat' | 'addItem' | 'addTag' | 'relation' | 'spawnEvent'; payload: Record<string, unknown>; }

// ---- 封印物 ----
interface SealedArtifact {
  code: string;                   // 如 "2-107"
  grade: 0 | 1 | 2 | 3;
  name: string; description: string;
  origin: string;                 // 来源：某途径某序列特性
  power: string; downside: string;
  containment: string; useCost: string;
  holderId: string | null;
}

// ---- 非凡特性总账 ----
type CharacteristicLedger = Record<string /* pathwayId */, Record<number /* seq */, number /* 现存份数 */>>;
```
